# 客户文件字段一致性验收

## 实现

- `imports.fields` 返回有序的实时字段定义，供客户列表导出和两个导入入口共同使用。
- 基础字段与原客户导出顺序一致，包含完整姓名、自定义字段、创建时间、更新时间；还支持客户档案状态、标签及动态属性。
- 模板每次下载都重新读取元数据。已定义但未赋值的客户属性、直接添加到客户档案的属性、自定义字段显示名称变更都会反映在下一次下载中。
- 自定义表头附带稳定字段标识，避免重名冲突，并支持显示名称变更后的自动映射。
- 导出按批读取档案，包含动态属性的实际值；仅具有联系人读取权限的用户继续导出基础字段，客户档案字段及值另需客户读取权限。
- 两个导入入口支持动态属性及数字、布尔、JSON 类型，保留 0、false、长编号、前导零；空值不覆盖现有值，系统维护列与只读属性不导入。
- 后台 CSV 支持带 BOM 的表头、引号、逗号和换行记录；属性类型在暂存时确定，避免排队期间字段配置变化导致重新解释。

## 验证范围

- 前端回归：ContactFileRoundTrip、contactImportFile、CustomerImportPanel、ContactsPage。
- Go 回归：TestContactFile、TestImportJob、TestLegacyContact；覆盖字段更新、权限、表头改名、类型转换、完整导入到 worker 的映射。
- PostgreSQL：使用独立连接的临时表运行真实元数据查询及批量档案读取；验证未赋值的新字段、直接档案属性、字段改名及客户权威值优先规则，不写入真实工作空间。
- 浏览器：使用真实页面与模拟业务接口，实际下载模板和导出文件；列名和顺序逐项比较一致，CSV 与 Excel 模板一致；新增字段后模板由 40 列增至 41 列，并立即显示修改后的字段名称。
- 浏览器下载的导出文件精确保留 `000123456789012345678`、数值 `0`、布尔值 `false`；动态属性导入另有真实组件回归与 Go worker 测试覆盖。
- TypeScript、修改文件 ESLint、前端生产构建、Go API 编译及 git diff --check。

浏览器接口模拟与 PostgreSQL / worker 验证为分开执行的检查，未宣称浏览器测试将数据写入真实业务库。
