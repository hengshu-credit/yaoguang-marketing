## 适配后的行为

### 消息与事务通知

- 元数据使用历史 `message_data.metadata`，支持布尔、数字、数组和对象；行内两项、其余展开查看。没有元数据或客户擦除后的空对象仍可展示。
- 日志页面可在列选择器开启“元数据”；嵌入式表格也支持该列。模板已删除、无法解析或渠道不是 Email 时，不影响表格查看元数据。
- 真实浏览器检查发现宽列会挤压中文表头，已补表格横向滚动；开启更多列不会把表头逐字挤成竖排，重载保留列选择。
- 预览抽屉仅在有元数据时增加页签，不覆盖瑶光 Email/Web/SMS/Push/通用渠道预览。
- 失败说明优先读取实际 API 的 `status_info`，兼容旧 `error`。没有把 `failed_at` 简单等同于“从未提交”：多渠道可能先被 Provider 接受，后来收到失败回执。
- 新建 Zapier Key 增加事务通知权限；不批量扩宽旧 Key，旧连接需要 Workspace owner 显式授权。没有接管外部 Zapier 应用的配置或发布。
- Transactional write 沿用已有资源权限语义，也允许维护事务通知，不是独立的 send-only 权限。第三方 Key 应按实际用途配置、妥善保管。
- 未配置 Email Provider 返回可修正的 400；泛化发送失败仍为 500，不让临时故障被客户端当成不可重试请求。

### 投递可靠性

- SMTP 服务器的多行拒绝说明保留到类型化错误及现有消息历史；分类依据命令阶段和状态码，而非只找“550”。
- 永久收件人错误不重试、不计 Provider 熔断；临时错误仍可重试。发送方、认证和策略拒绝仍按 Provider 问题处理，避免将全局配置问题误认成名单质量问题。
- 保留瑶光现有 `DeliveryIntent`、Effect Key、Claim、unknown 对账及终态证据。上游“保留失败队列七天并重新发送”的按钮没有直接加入。
- 上游旧 Broadcast/Analytics 的 Sent 统计修复未直接套用：瑶光 `sent_at` 的历史兼容字段与多渠道晚到失败回执不能用一个 `failed_at IS NULL` 谓词无损重解释。后续应基于 Delivery 接受证据统一新旧统计并对账；本轮未改历史统计或声称该项已完成。

### Webhook 网络策略

- 订阅保存时拒绝明显私网/保留地址；实际请求在 DNS 解析和每次重定向连接时再次检查，避免 DNS 重绑定。
- 订阅投递、Journey Webhook 节点和签名多渠道 Provider 默认使用受保护客户端；供应商专用客户端不受此开关影响。
- 连接前的网络策略拒绝不会给订阅增加自动退役计数。已有投递仍遵守次数上限，可能成为明确失败，**不会无限重试或承诺自动恢复所有已耗尽投递**。
- 签名渠道的连接前阻断是明确失败，不记为可能已发生的 `unknown`。其禁止重定向和签名/Effect Key 行为保持不变。
- 内网自托管确需调用私网服务时设置 `YAOGUANG_WEBHOOK_ALLOW_PRIVATE_HOSTS=true`，重启相应服务；该设置放宽整个部署的 Webhook 出站范围，应仅在可信部署开启。兼容 `WEBHOOK_DELIVERY_ALLOW_PRIVATE_HOSTS`，但显式瑶光变量优先。两个 Compose 拓扑都已透传，默认 false。

### AI、请求关联与安全依赖

- 邮件和博客助手要求先完成正文/结构，再更新标题。营销用途保留退订与通知中心链接，事务用途不凭空添加缺失的名单变量，`opt_in` 使用实际 `confirm_subscription_url`。
- 自定义模板分类读取配置中的 purpose，不用硬编码分类名猜用途。
- 仅当编辑工具已执行而没有文字回复时，允许额外一次只读说明请求。第二次请求没有编辑工具，前端也拒绝执行该轮任何编辑调用；已有文字或截断/失败时不追加。默认和分析助手的工具循环语义不变。
- 全局 `X-Request-ID` 复用 Customer API 的 128 字符白名单规则，响应头和响应体一致；CORS 允许传入/读取该头，Debug 请求日志携带关联 ID，不记录 query/body。
- 三个前端使用修补后的 Vitest 4.1.11；同步修正测试 Mock 类型。更新 Tiptap、fflate、js-yaml 及告警对应的间接依赖。两个 Go 模块更新 gRPC，telemetry 同步 x/crypto、x/net 及必要传递依赖；生产运行基镜像改为 Alpine 3.24。
- Alpine 3.24 的支持状态由[官方发布表](https://alpinelinux.org/releases/)核实；本机 Docker Registry manifest 查询超时，未声称已经拉取或重建此生产镜像。
- 保留瑶光版本 57.0、不改数据库版本、不运行迁移，不复制上游许可/遥测扩展。
