# 瑶光内容中心与数据分析二级页签恢复设计

**日期：** 2026-08-30

**状态：** 已确认，进入实施

## 1. 背景与结论

瑶光营销平台在建立九个业务域一级导航时，将 Notifuse v39.0 原有的内容和网站分析子入口合并为单个一级入口。页面文件和路由仍然存在，但入口被隐藏，导致用户误以为模板之外的内容管理以及多个数据分析能力已经被删除。

本次采用“一级业务域不变、域内页面页签恢复”的方案：

- 左侧继续保留九个扁平一级菜单，不恢复折叠侧栏或侧栏二级菜单；
- 内容中心和数据分析在页面顶部使用统一的路由型二级页签；
- 保留现有页面、URL、权限和新增瑶光能力，不复制或重写原业务功能；
- 所有页签均可深链接、刷新、收藏并支持浏览器前进和后退。

## 2. 信息架构

### 2.1 一级导航

继续保留：

1. 工作台；
2. 客户；
3. 客群；
4. 营销活动；
5. 自动化旅程；
6. 内容中心；
7. 数据分析；
8. 投递中心；
9. 设置。

侧栏不得出现 Ant Design SubMenu，内容中心和数据分析的子页面不得增加为新的一级入口。

### 2.2 内容中心页签

| 页签 | 路由 | 现有能力 |
|---|---|---|
| 模板管理 | `/templates` | Email、SMS、Push 等消息模板管理 |
| 文章管理 | `/blog` | 文章、分类和 blog 管理 |
| 文件管理 | `/file-manager` | 文件上传、目录和素材管理 |

左侧“内容中心”默认进入当前用户第一个有权访问的页签：模板管理优先，其次 文章管理，再次文件管理。现有权限模型中 Blog 和文件管理均沿用 Workspace 权限，不新增权限资源。

### 2.3 数据分析页签

| 页签 | 路由 | 瑶光适配后的用途 |
|---|---|---|
| 营销概览 | `/analytics` | 客户增长、营销/事务触达、送达、打开、点击和失败消息 |
| 网站概览 | `/web-analytics/dashboard` | 网站会话、来源、内容和访问质量概览 |
| 实时访客 | `/web-analytics/live` | 最近 30 分钟访客、页面、地域、来源和设备 |
| 多维分析 | `/web-analytics/explore` | 自定义维度、预设报表和 CSV 导出 |
| 转化目标 | `/web-analytics/goals` | 目标次数、转化率和目标价值 |
| 归因规则 | `/web-analytics/filters` | 流量渠道映射、字段改写、规则测试和历史回填 |
| 分析标注 | `/web-analytics/annotations` | 营销活动、发布、故障等时间线解释标记 |

营销概览需要 Message History 读取权限；其余网站分析页签需要 Web Analytics 读取权限。左侧“数据分析”在有 Message History 权限时优先进入营销概览，否则进入网站概览；无任一权限时不显示。

## 3. 交互与视觉

- 页签位于页面标题区域下方、页面功能工具栏上方，作为域内稳定导航；
- 使用受控 `activeKey`，当前路由与高亮页签必须始终一致；
- 页签本身使用路由链接，不通过本地状态切换页面；
- 窄屏允许横向滚动页签栏，但不得造成整个文档横向滚动；
- 页面继续保留各自原有标题、搜索、筛选、创建、时间范围和导出操作；
- 实时访客页不再只提供返回网站概览的单一路径，必须显示完整数据分析页签；
- 数据分析各页签使用面向营销运营人员的中文术语，但不改变底层 API、schema 或路由参数。

## 4. 技术设计

新增聚焦于导航的组件：

- `PageSectionTabs`：渲染可访问的路由型 Ant Design Tabs；
- `ContentCenterTabs`：定义内容中心的三条路由和权限过滤；
- `DataAnalyticsTabs`：定义数据分析的七条路由和权限过滤。

组件只负责域内导航，不获取页面业务数据。现有 TemplatesPage、BlogPage、FileManagerPage、AnalyticsPage、WebAnalyticsPage 和 WebAnalyticsLivePage 分别传入明确的 active key。

不重构 TanStack Router 的父子路由树，避免破坏现有页面中 `useParams({ from: ... })`、搜索参数校验和历史深链接。

`WorkspaceLayout` 只调整两个一级入口的权限和默认目标：

- 内容中心继续维持模板优先的权限回退；
- 数据分析从仅检查 `web_analytics` 改为检查 `message_history || web_analytics`，并按权限选择 `/analytics` 或网站概览。

## 5. 权限与异常行为

- 只渲染当前用户具备读取能力的页签；
- 权限加载期间保留稳定占位，避免先显示后消失造成误点；
- 当前页面对应页签必须在允许访问时高亮；
- 直接访问无权限旧 URL 继续由现有 API 权限和页面错误边界处理，本次不扩大后端授权范围；
- Workspace 切换后重新计算页签权限，不能复用前一个 Workspace 的可见性。

## 6. 测试与验收

1. 左侧仍严格只有九个一级菜单且没有 SubMenu。
2. 内容中心三个旧路由分别高亮模板管理、文章管理和文件管理。
3. 数据分析七个路由分别高亮正确页签。
4. 页签链接保留 workspaceId 和原有 route 结构。
5. 模板权限不足时内容中心默认进入 文章管理。
6. 只有 Message History 权限时仍显示数据分析并默认进入营销概览。
7. 只有 Web Analytics 权限时数据分析默认进入网站概览，且不展示营销概览页签。
8. 实时访客页面显示完整数据分析二级页签。
9. 现有 WorkspaceLayout 导航测试、Web Analytics 路由测试、TypeScript 构建和 ESLint 全部通过。

## 7. 非目标

- 不恢复 Notifuse 原侧栏折叠菜单；
- 不新增后端接口或数据库迁移；
- 不合并 Blog 内部分类侧栏或模板内部分类筛选；
- 不改变网站分析采集、查询、AI 助手、归因规则或标注的业务语义；
- 不删除或重定向现有公开 URL。
